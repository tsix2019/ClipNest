## 四、我自主做的决定（可以改）

| 决定 | 原因 |
|---|---|
| 默认快捷键用 `Ctrl+Shift+V`，Paste Stack 用 `Ctrl+Shift+C` | `Win+V` 被系统剪贴板历史占用；这两个和 Paste 的 Shift+Cmd+V / Shift+Cmd+C 对应 |
| 数据库用 Windows 自带的 `winsqlite3.dll` | 零依赖、零体积；系统自带版本是 3.51，支持 FTS5 trigram |
| 多语言用嵌入式 JSON 字符串表，不用 .resw/MRT | 不打包分发的 WinUI 应用里 MRT 的语言覆盖不可靠；JSON 对翻译贡献者更友好，也兼容 AOT |
| Windows App SDK 只引用 WinUI、Foundation、InteractiveExperiences 三个组件包 | 完整元包会拉进 AI / ML / Widgets，体积大、下载多 |
| 发布版用 Native AOT + 自包含，只在 CI 构建 | 本地 AOT 需要额外下载约 200 MB 的包，你的网络流量贵 |
| 录屏时隐藏、忽略敏感内容默认开启；开机启动默认开启（引导页里可以关） | 隐私优先 |
| 粘贴后被粘贴的条目移到最前 | 与 Paste 的行为一致 |
| 卡片头部颜色取来源 App 图标的主色，并自动调到满足 4.5:1 的文字对比度 | 调研结论倾向于 Paste 就是按来源 App 着色 |
| 暂不添加 LICENSE 文件 | 你还没决定开源协议 |
| 加了调试用环境变量：`CLIPNEST_DATA`（换数据目录）、`CLIPNEST_SNAPSHOT`（渲染截图后退出）；加了启动参数 `--toggle` | 用于测试和 CI；`--toggle` 也可以绑定到其他快捷工具 |

## 五、已知不足 / 后续可做

- 私有内存 64 MB，比 60 MB 的目标略高。可以考虑长时间不用时销毁面板窗口，代价是下次打开要慢 100–200 ms。
- Pinboard 标签还不能拖动排序（仓储层已有 `ReorderPinboards`，只差界面）。
- 搜索筛选条件还没有以“标签胶囊”的形式显示在搜索框里，目前是文本形式加筛选菜单。
- 预览窗口里的链接只显示标题和 URL，不内嵌网页（为了不引入 WebView2 的运行时开销）。
- 没有跨设备同步（设计上明确不做）。
- 单条目专属快捷键、文本变换（JSON 格式化、大小写转换等）留作差异化功能。
- CI 提示 GitHub Actions 的 Node 20 即将弃用，后续把 `actions/*` 升级到新的主版本即可。
