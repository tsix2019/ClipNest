# ClipNest 1.1 — feature batch design

Date: 2026-10-21. Decisions confirmed with the user in chat.

## 1. Bug: typing in a flyout text box acts on the cards
`PanelWindow.Root_PreviewKeyDown` sees keys from flyout text boxes (new/edit pinboard, rename).
Backspace/Delete deleted the selected cards, Enter pasted, Space previewed.
Fix: when the focused element (`FocusManager.GetFocusedElement(Content.XamlRoot)`) or the event source
is a `TextBox` other than `SearchBox`, return before any shortcut handling; `Root_CharacterReceived`
does the same.

## 2. Delete confirmation
Delete/Backspace and the context-menu "Delete" open a confirmation flyout anchored on the first selected
card: "Delete N items?" + Delete button. Enter/Delete button confirms, Esc cancels. Ctrl+Z undo unchanged.
Deleting a pinboard already confirms.

## 3. Pin to top ("置顶")
- Schema v2: `ALTER TABLE items ADD COLUMN top INTEGER NOT NULL DEFAULT 0` (0 = normal, otherwise a
  timestamp so the most recently pinned comes first).
- `ClipItem.TopAt` (long). Query order: `items.top DESC, items.created_at DESC, items.id DESC`.
- Retention (`PurgeOlderThan`, `EnforceCap`, `ClearHistory`) never removes top items.
- Card menu: "Pin to top" / "Unpin from top"; card header shows a small pin glyph.
- Backup/restore and Restore() carry the column.

## 4. Snippets (user-written text)
- Card list area: when a pinboard tab is selected, a "New text" button appears in the top bar.
  On the history tab it also appears; text created there goes into a pinboard named "常用"/"Snippets",
  created on first use.
- Opens the existing `EditWindow` in "create" mode (empty text, Save creates the item via
  `AppHost.CreateSnippet(text, pinboardId)` → `ClipKind.Text`, hash `ContentHasher.ForText`). If the
  same text already exists, that item is moved into the pinboard instead.
- Placeholders ({date}, {clipboard}, …) already expand for pinned items.

## 5. Win+V
- Setting `UseWinV` (default false), toggle under Shortcuts.
- `WinVHook`: a low-level keyboard hook installed while the setting is on. On V keydown with a Win key
  held (and not our own injected input) it swallows the key, sends a dummy key (VK 0xFF) so releasing
  Win does not open Start, and posts "toggle panel" to the UI thread. Key-up of that V is swallowed too.
- Off → hook removed, Windows' own Win+V works again.

## 6. Update check (manual)
- About page: "Check for updates" button + result text.
- GET `https://api.github.com/repos/tsix2019/ClipNest/releases/latest` (User-Agent ClipNest, ~5 KB),
  compare `tag_name` (vX.Y.Z) to the assembly version. Newer → show "Version X available" + button that
  opens the release page in the browser. No automatic checks, no downloads.

## 7. About page
Adds rows: GitHub (https://github.com/tsix2019/ClipNest, opens browser) and contact email
tsix2019@gmail.com (mailto:, plus copy).

## 8. Panel position
- Setting `PanelEdge`: "bottom" (default) | "top" | "left" | "right".
- Bottom/top: full-width strip, height = `PanelHeight`. Left/right: full-height column, width =
  `PanelWidth` (default 340 DIP, 280–560), cards stacked vertically.
- `CardList` items panel orientation follows the edge (set in code by swapping `ItemsPanel`).
- Resize grip sits on the inner edge (top for bottom, bottom for top, right for left, left for right).
- Vertical layout: arrow Up/Down move selection; Up from the first card goes to search.
- Settings → General: "Panel position" combo; applied on next open.

## 9. Animation
- Show: the window slides in from its edge (≈200 ms, ease-out) by moving the AppWindow per frame
  (`CompositionTarget.Rendering`), together with the existing content fade.
- Hide: content fade only (fast), as now.
- Card scrolling: keyboard selection and the mouse wheel scroll with `ChangeView(..., disableAnimation:false)`
  instead of jumping; vertical wheel over the horizontal list scrolls it horizontally.

## 10. Font
- Setting `FontFamily` (null = system default). Settings → General: font combo listing installed
  families (DirectWrite system collection, localized names), first entry "System default".
- Applied app-wide by overriding `ContentControlThemeFontFamily` in `Application.Resources` before
  windows are created, and on change for already-open windows (panel/settings re-render). Card text
  style and code font for code-like text stay as they are, except that the card body uses the chosen
  family when not code.

## Out of scope
Automatic update downloads, registry changes to Windows' Win+V.

## Testing
- Core: repository ordering/retention with top items, snippet creation, version comparison.
- Manual on the real desktop: flyout typing, delete confirmation, Win+V, four panel edges, animation, font.
